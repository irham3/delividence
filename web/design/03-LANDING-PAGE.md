# Landing Page — Approved Structure

Reference: [landing-final.png](previews/landing-final.png). The page sells a concrete product flow, not an implementation stack.

## Navigation

`Delividence` · `Workflow` · `Review` · `About` · `Sign in` · `Create a record`

The header is visually quiet, sticky after the first viewport, and uses a solid canvas background after it becomes sticky. Mobile shows the wordmark, `Sign in`, and a menu sheet; never hide the CTA behind the menu.

## Scene map

| # | Scene | Job | Visual / motion |
| --- | --- | --- |
| 1 | Hero | Reframe the brief as incomplete project material. | Source artifacts and index dock into a record. |
| 2 | Material → record | Prove multimodal intake without listing model features. | Pinned source rail fans, aligns, and docks. |
| 3 | Decision | Show the agent asks a bounded question; client retains authority. | Pinned question, client choice, record update. |
| 4 | Change path | Explain no silent mutation. | Request meets boundary and reroutes to change decision. |
| 5 | Proof | Show acceptance against criteria. | Horizontal evidence reel with fixed criterion rail. |
| 6 | Provenance | Give lightweight production credibility. | Source → resume → version spine. |
| 7 | CTA | Convert. | Large quiet final statement. |

### 1. Hero

**Eyebrow:** `One place for the material behind the work`  
**Headline:** `The brief is more than the brief.`  
**Body:** `Emails, notes, images, and calls become a record the project can actually use.`  
**CTAs:** `Create a record` / `See a sample`

Hero sources must be DOM product fragments, not a raster screenshot. They are semantic examples: email, call transcript, visual reference, and source index. Decorative pencil/paperclip elements are allowed here only and have empty alt text.

### 2. Watch the material become a record

Do not render five equal feature cards. Use a pinned stage 150–180vh tall. A staggered source rail enters on the left and resolves into a single Project Record on the right.

Microcopy: `What was said.` / `What was shown.` / `What remains unclear.`

### 3. The record asks for a decision, not another conversation

Use the current priority question as the focal element. Cite the sources that produced it and show the client’s secure choice. A margin annotation states: `Only the client resolves conflicting client statements.`

This scene is central to the Collaborative Partner category: the system guides and resumes; it does not decide what a client meant.

### 4. New work takes a separate path

Keep the shared limestone canvas. A baseline paper holds position on the left. A request arrives, meets a graphite boundary, then follows the saffron route to a new change decision. The baseline must remain visibly unchanged.

Captions: `Baseline stays.` / `Request arrives.` / `Decision is recorded.`

### 5. Put the proof beside the promise

The active criterion sticks left while screenshot, video, URL, and document evidence travel through a horizontal reel. The client controls `Accept` or `Request changes`. Use the caption: `Visual checks assist the review. The client decides.`

### 6. A record that keeps its place

One provenance spine replaces a generic feature grid:

`Source linked` → `Workflow resumed` → `Version retained`

Each node displays a short real-looking reference: source ID, time, actor, and version. The small technical footnote reads: `Built with Gemini 3.5, Google ADK, and Google Cloud.`

### 7. CTA

**Headline:** `Give the work a record worth returning to.`  
**Action:** `Create a record`

## What to highlight for the hackathon

The landing demonstrates the value judges need to understand: multiple input formats, an agent-directed clarification loop, a secure client feedback step that resumes work, versioned scope control, and criterion-level proof. Do not put Firestore, Pub/Sub, or Cloud Run in hero copy. They belong in the demo, architecture diagram, repository, and the small production footnote.
